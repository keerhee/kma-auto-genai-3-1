# P8 · 명령어·프롬프트 총정리와 응용 실습

> **요약.** P0~P7에서 등장한 모든 명령어·프롬프트를 한곳에 모으고, 과정 전체를 적용하는 10개 실습과제와 모범답안을 제공한다. 앞부분은 빠르게 찾아보는 레퍼런스, 뒷부분은 직접 손으로 짜 보는 실습이다. 명령어 다수는 실험 기능이라 버전과 함께 표기했다.

## A. 명령어·프롬프트 총정리

### A-1. 환경 설정·활성화

| 항목 | 내용 | 비고 |
|---|---|---|
| `export CLAUDE_CODE_EXPERIMENTAL_AGENT_TEAMS=1` | Agent Team 기능 활성화 | Claude Code v2.1.32+ |
| `settings.json`의 `"env": { ... }` | 환경 변수를 세션에 영속화 | `~/.claude/settings.json` |
| Hooks v2 | 27개 수명주기 이벤트 | v2.1.141+ |

`~/.claude/settings.json` 예시:

```json
{
  "env": {
    "CLAUDE_CODE_EXPERIMENTAL_AGENT_TEAMS": "1"
  }
}
```

### A-2. 플러그인·마켓플레이스

| 명령 | 역할 |
|---|---|
| `/plugin marketplace add <owner/repo>` | 마켓플레이스 등록 |
| `/plugin install <name>@<marketplace>` | 플러그인 설치 (예: `harness@harness`) |
| `/<plugin>:<command>` | 네임스페이스 슬래시 명령 (예: `/security:scan`) |
| `cp -r skills/<name> ~/.claude/skills/<name>` | 수동(전역) 설치 |

### A-3. 메타 하네스 (revfactory/harness)

```bash
export CLAUDE_CODE_EXPERIMENTAL_AGENT_TEAMS=1
/plugin marketplace add revfactory/harness
/plugin install harness@harness
```

호출은 평문 한 문장으로 한다. 한국어 "하네스 구성해줘", 영어 "build a harness for this project". 새 에이전트·스킬을 다시 읽게 하려면 세션을 `/exit`로 닫았다 여는 편이 안전하다.

### A-4. 실행 경로 (Dynamic Workflow, 2026.05.28+)

| 명령 | 역할 |
|---|---|
| `/deep-research` | 번들 리서치 워크플로우 (Scope→Search→Fetch→Verify→Synthesize) |
| `/effort ultracode` | 자동 워크플로 오케스트레이션 (파악–변경–검증 루프) |
| `/workflow` | 커스텀 워크플로 직접 설계 |
| `/workflows` | 진행 중 워크플로의 단계·에이전트 수·토큰·시간 조회 |

### A-5. 세션·비용 관리

| 명령 | 역할 |
|---|---|
| `/clear` | 컨텍스트 초기화 (디스패치 사이 토큰 30~50% 절감) |
| `/stop` | 유휴 에이전트 종료 |
| `/exit` | 세션 종료 (설정·에이전트·스킬 재로딩) |
| autocompact | 약 187K 토큰에서 자동 발동 |

### A-6. 워크플로 프리미티브 (Claude가 작성하는 스크립트)

| 프리미티브 | 역할 |
|---|---|
| `agent()` | 하나의 에이전트 — 한 작업 수행 |
| `parallel()` | 여러 에이전트를 동시에 실행 (펼침) |
| `pipeline()` | 여러 에이전트를 순서대로 실행 (사슬) |
| `workflow()` | 위를 묶어 재사용 가능한 하네스로 |

### A-7. 5요소 파일·구조

```text
project/
├── CLAUDE.md                      # 프로젝트 메모리·규칙 (매 세션 로드)
└── .claude/
    ├── settings.json              # 환경 변수 · 훅
    ├── agents/<name>.md           # 서브에이전트 정의
    └── skills/<name>/SKILL.md     # 스킬 정의
```

플러그인은 위 부품을 묶어 마켓플레이스로 배포한다. MCP는 외부 시스템·데이터 연결을 담당한다.

### A-8. 훅 이벤트·exit 코드

| 이벤트 | 발화 시점 |
|---|---|
| `SessionStart` | 세션 시작 시 컨텍스트 주입 |
| `UserPromptSubmit` | 프롬프트 제출 직후 검사 |
| `PreToolUse` | 도구 실행 직전 — 차단 게이트 |
| `PostToolUse` | 도구 실행 직후 — 린트·로그 |
| `Stop` | 종료 시 요약·커밋 |

exit 코드: `0` 통과, `2` 차단, `1` 비차단 오류(동작은 그대로 진행).

### A-9. 정의 frontmatter

에이전트(`.claude/agents/*.md`)는 `name`·`description`·`tools`를, 스킬(`SKILL.md`)은 `name`·`description`(트리거 설명 포함)을 가진다.

### A-10. 호출 프롬프트 패턴

- 하네스 자동 생성: "하네스 구성해줘"
- 에이전트 팀: "<도메인>을 리팩터링할 에이전트 팀을 구성하라. 팀원 셋을 스폰한다 — A / B / C. 공유 작업목록으로 조율하게 하라."
- 딥 리서치: "<주제>에 대한 딥 리서치 파이프라인을 구성해줘."

## B. 응용 실습과제 10선과 모범답안

각 과제는 목표, 지시, 모범답안으로 구성된다. 모범답안은 한 가지 정답이 아니라 좋은 출발점이다.

### 과제 1 — 최소한의 CLAUDE.md 작성 (P1)

**목표.** 항상 지켜야 할 규칙만 담은 가벼운 `CLAUDE.md`를 만든다. 절차 문서로 비대해지지 않게 한다.

**모범답안.**

```markdown
# 프로젝트: 사내 리서치 자동화

## 원칙
- 출력은 한국어. 결론을 먼저, 근거를 뒤에.
- 외부 사실은 반드시 출처를 함께 남긴다.

## 자주 쓰는 명령
- 리서치: `/deep-research`
- 케이스 작성 스킬: case-writer

## 하네스 포인터
- 새 작업 요청 시 orchestrator 스킬을 먼저 검토한다.
```

핵심은 "항상 필요한 규칙"만 둔 것이다. 작업별 절차는 스킬로 분리한다.

### 과제 2 — 첫 스킬 만들기 (P1·P2)

**목표.** 반복하지만 매번 조금 다른 작업 하나를 `SKILL.md`로 패키지화한다.

**모범답안.** `.claude/skills/weekly-report/SKILL.md`

```markdown
---
name: weekly-report
description: 주간 업무 보고서 초안 작성. "주간 보고" 요청 시 트리거.
---

# 주간 보고 절차
1. 이번 주 완료 항목을 3~5개로 추린다.
2. 각 항목: 무엇을 / 왜 / 다음 액션 순으로 한 줄.
3. 톤은 간결한 평서문. 과장·수식어 배제.
4. 마지막에 다음 주 우선순위 3개를 덧붙인다.
```

### 과제 3 — 서브에이전트 정의 (P1·P3)

**목표.** 메인 세션을 더럽히지 않고 큰 조사를 맡길 격리 워커를 정의한다.

**모범답안.** `.claude/agents/researcher.md`

```markdown
---
name: researcher
description: 주제를 조사하고 핵심 근거를 정리한다.
tools: [web_search, web_fetch, read]
---

너는 리서치 전문가다.
- 1차 출처를 우선하고, 모든 주장에 출처를 남긴다.
- 결과는 핵심 주장 + 근거 + 출처 형식의 요약만 보고한다.
```

`tools`를 조사에 필요한 것으로 좁혀, 권한과 컨텍스트를 깨끗하게 유지한 점이 핵심이다.

### 과제 4 — PreToolUse 보안 훅 (P1)

**목표.** 위험한 명령을 LLM 판단 없이 결정적으로 차단한다.

**모범답안.** `PreToolUse` 훅 스크립트(개념)

```bash
#!/usr/bin/env bash
# 입력으로 실행 예정 명령을 받는다고 가정
CMD="$1"
if echo "$CMD" | grep -Eq 'rm -rf /| --force push'; then
  echo "위험 명령 차단" >&2
  exit 2     # 차단
fi
exit 0       # 통과
```

차단은 반드시 `exit 2`다. `exit 1`은 비차단 오류로 동작이 그대로 진행되므로 게이트로 쓰면 안 된다.

### 과제 5 — 단일 vs 팀 선택 판단 (P3)

**목표.** 주어진 작업에 SubAgent와 Agent Team 중 무엇이 맞는지 판단하고 근거를 댄다.

**지시.** 작업 A: "코드베이스 전체에서 사용하지 않는 import 30개를 제거". 작업 B: "신규 결제 기능을 API·DB·테스트 세 갈래로 동시에 개발하며 서로 인터페이스를 맞춰야 함".

**모범답안.**

- 작업 A → SubAgent. 각 수정이 독립적이고 서로 통신할 필요가 없다. 결과만 회수하면 된다.
- 작업 B → Agent Team. 세 갈래가 인터페이스를 맞춰야 하므로 팀원 간 직접 통신과 공유 작업목록이 필요하다.

판단 기준은 "서로 결과를 봐야 하는가"이다.

### 과제 6 — Agent Team 구성 프롬프트 (P3)

**목표.** 결제 모듈 리팩터링을 위한 3인 팀을 한 문장으로 구성한다.

**모범답안.**

```text
결제 모듈을 리팩터링할 에이전트 팀을 구성하라.
팀원 셋을 스폰한다 — API 계층 / DB 마이그레이션 / 테스트 커버리지.
공유 작업목록으로 서로 조율하고, 인터페이스 변경은 즉시 공유하라.
```

사전 조건: `settings.json`에 `CLAUDE_CODE_EXPERIMENTAL_AGENT_TEAMS=1`. 비용을 줄이려면 단순 팀원은 경량 모델로 티어링하고, 유휴 시 `/stop`.

### 과제 7 — 메타 하네스로 도메인 하네스 생성 (P4)

**목표.** 본인 도메인의 하네스를 자동 생성하고, 생성물을 검토한다.

**모범답안.** 호출과 검토 절차

```text
딥 리서치 파이프라인을 위한 하네스를 구성해줘.
```

검토 포인트: (1) Phase 2에서 고른 팀 패턴이 도메인에 맞는가, (2) `.claude/agents/`의 역할 경계가 너무 넓지 않은가, (3) 검증 단계(Producer-Reviewer)가 포함됐는가. 부족하면 "확장" 모드로 다시 돌려 검수 게이트를 추가한다.

### 과제 8 — Fan out → Reduce → Synthesize 설계 (P5)

**목표.** 다섯 출처를 동시에 조사해 하나의 결론으로 합치는 워크플로를 설계한다.

**모범답안.** 의사코드

```javascript
const sources = ["A", "B", "C", "D", "E"];
// Fan out: 출처마다 독립 에이전트
const findings = await parallel(
  sources.map(s => agent("researcher", { source: s }))
);
// Reduce: 중복 제거·충돌 표시
const merged = dedupeAndFlag(findings);
// Synthesize: 신뢰도순 정렬 + 인용
return await agent("synthesizer", { merged });
```

한 단계의 출력이 다음 단계를 결정하므로 단순 fan-out이 아니라 워크플로다.

### 과제 9 — 품질 검증 루프 적용 (P5)

**목표.** 과제 8의 결과에 Adversarial Verify를 끼워 환각을 거른다.

**모범답안.** 검증 단계 추가

```javascript
// Synthesize 직전에 반박 단계
const verified = await parallel(
  merged.claims.map(c => agent("verifier", {
    claim: c, task: "이 주장을 반박할 근거를 찾아라"
  }))
);
const survived = merged.claims.filter(c => !refuted(verified, c));
```

원칙은 "자기 숙제를 자기가 채점하지 않는다" — 검증은 별도 에이전트가, 가능하면 별도 컨텍스트에서 수행한다.

### 과제 10 — SSOT 설계 (P6)

**목표.** 여러 에이전트가 협업할 때 일관성이 무너지지 않도록 단일 진실 원천을 설계한다.

**모범답안.** `character_sheet.json` (브랜드 가이드로 응용)

```json
{
  "brand": "Nutri Co.",
  "tone": ["신뢰감", "간결", "근거 중심"],
  "palette": { "primary": "#1B5E20", "accent": "#E65100" },
  "forbidden": ["과장 표현", "효능 단정"]
}
```

기획·작화·카피·검수 에이전트가 모두 이 파일을 참조하면, 한 곳만 고쳐도 전체가 일관되게 따라온다.

## C. 마무리

명령어는 도구일 뿐이다. 무엇을 왜 시킬지(P7)가 분명할 때 이 도구들이 의미를 가진다. 위 10과제를 본인 도메인의 실제 작업으로 바꿔 한 번씩 손으로 짜 보는 것이 이 과정의 가장 좋은 복습이다.

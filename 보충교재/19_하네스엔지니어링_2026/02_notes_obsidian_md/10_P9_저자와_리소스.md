# P9 · 저자와 리소스 — revfactory · harness-100

> **요약.** 이 과정에서 다룬 메타 하네스와 하네스 컬렉션은 황민호(robin.hwang)님이 공개한 오픈소스다. 세 저장소를 소개하고, 설치·복사로 바로 시작하는 법을 정리하며 과정을 마친다.

## 저자

황민호(Minho Hwang · robin.hwang)는 카카오 AI Native 전략 팀 리더다. 2013년부터 카카오에서 Daum 검색, 광고 플랫폼 Moment, 오픈소스 관리 플랫폼 OLIVE 등을 개발했고, 현재 AI Agent를 비롯한 최신 AI 트렌드를 선제적으로 탐구하며 오픈소스에 적극 기여한다. GitHub: `github.com/revfactory`

|---|---|---|
| `revfactory/harness` | 메타 하네스 (팀 아키텍처 팩토리) | "하네스 구성해줘"로 팀·스킬 자동 생성 |
| `revfactory/harness-100` | 기성 하네스 100개 컬렉션 | 10개 도메인 · 한영 200패키지 · 1,808개 마크다운 |
| `revfactory/claude-code-harness` | 효과 통제 실험 | 평균 +60%(49.5→79.3), 15/15, −32% 분산 (n=15, 저자 A/B) |

## harness — 설치와 호출

```bash
export CLAUDE_CODE_EXPERIMENTAL_AGENT_TEAMS=1
/plugin marketplace add revfactory/harness
/plugin install harness@harness
```

호출은 평문 한 문장. "하네스 구성해줘" / "build a harness for this project" / "ハーネスを構成して". 새 에이전트·스킬을 다시 읽게 하려면 `/exit`로 세션을 닫았다 연다.

## harness-100 — 구조와 사용법

각 하네스는 동일한 구조를 따른다.

```text
{NN}-{harness-name}/
└── .claude/
    ├── CLAUDE.md              # 프로젝트 개요
    ├── agents/                # 전문 에이전트 4~5 + 교차 검증
    └── skills/
        └── {orchestrator}/skill.md
```

가까운 도메인의 `.claude/` 폴더를 내 프로젝트로 복사하면 바로 쓸 수 있다.

```bash
# 한국어 하네스
cp -r ko/01-youtube-production/.claude/ /path/to/my-project/.claude/
# 영어 버전
cp -r en/01-youtube-production/.claude/ /path/to/my-project/.claude/
```

각 폴더의 `CLAUDE.md`에 구조와 사용법이 들어 있다. 모든 하네스는 에이전트 팀 모드(직접 통신·교차 검증), 산출물 템플릿, 의존 관계 관리, 에러 핸들링, 규모별 모드(풀/축소/단일), 테스트 시나리오 3종을 충족한다. 브라우저에서 검색·설치하는 커뮤니티 웹 카탈로그도 있다.

## 시작하는 두 가지 길

기성품 복사로 빠르게 출발하거나(harness-100), 메타 하네스로 도메인에 맞게 새로 생성한다(harness). 어느 쪽이든 생성물의 역할 경계와 검증 단계를 사람이 검토하는 것이 핵심이다.

## 마무리

모델은 충분히 똑똑하다. 차이는 운영 구조와 방향에서 난다. 기성품을 복사해 보고, 한 문장으로 만들어 보고, 직접 검증하는 것이 시작이다.

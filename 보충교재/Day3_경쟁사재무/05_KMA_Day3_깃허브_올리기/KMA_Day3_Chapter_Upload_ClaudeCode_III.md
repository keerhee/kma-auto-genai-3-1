# 백지에서 시작하는 챕터 올리기 — 메타 프롬프트판

> [!summary] 이 판의 핵심
> 수강생은 긴 프롬프트를 **직접 쓰지 않는다**. 아래 **메타 프롬프트**를 그대로 붙여 넣으면, Claude Code가 필요한 것을 **하나씩 묻고**, 할 일을 **스스로 계획**하고, 허락받아 **실행**한다.
> 수강생이 하는 일: **복사 → 질문에 답하기(대부분 숫자) → 허락 → 눈으로 확인.**

> [!info] 시작 전 확인
> - Claude 데스크톱 앱 설치·로그인, **Code** 탭 사용 가능 (Day 0 `Day0_4_Claude_설치가이드`)
> - GitHub 계정 — 없어도 된다. 3장의 가입 도우미로 함께 만든다
> - Git·강의 자료 — 미리 받지 않아도 된다. 3장의 시작 도우미가 받아 온다

| 처음 한 번 | Claude 입력창 | ✍ **M0** 붙여넣기 | 4.1 |

> [!danger] 비밀번호와 인증 코드는 Claude 입력창에 절대 넣지 않는다
> 가입 비밀번호, 이메일 인증 코드, 일회용 로그인 코드는 **브라우저에만** 입력한다.

## 0. 큰 그림 — 내 컴퓨터와 GitHub 사이에서 무엇이 오가나

수강생 컴퓨터에는 **상위 폴더 하나(`KMA_3-1`) 안에 두 폴더**를 나란히 둔다. Claude 데스크톱 앱의 Code 탭에서는 상위 폴더 `KMA_3-1`을 연다.

```text
KMA_3-1/                     ← Claude Code가 여는 폴더 (작업 규칙 CLAUDE.md도 여기)
├─ kma-auto-genai-3-1/       ← 선생님 강의 저장소의 사본 — 받기만 한다
│  ├─ Day3_경쟁사재무/  (강의 덱 PDF)
│  └─ data/Day3/        (실습 데이터)
└─ my-kma-auto-ai/           ← 내 학습 저장소 — 챕터를 쌓아 올린다
   ├─ README.md
   ├─ Day3_경쟁사재무/
   ├─ data/Day3/
   └─ 00_오늘결과물/      (GitHub에 올라가지 않는 임시 보관함)
```

| 폴더 | 어디서 오나 · 어디로 가나 | Git 동작 | 권한 |
|---|---|---|---|
| `kma-auto-genai-3-1/` | 선생님 GitHub → **내 컴퓨터** | `clone`(처음) · `pull`(매일 새로 받기) | 받기만. 수강생은 선생님 저장소에 올릴 권한이 없다 |
| `my-kma-auto-ai/` | **내 컴퓨터** → 내 GitHub | `commit` · `push` | 내 저장소라 올릴 수 있다 |

- **챕터 올리기 = 내 컴퓨터의 `my-kma-auto-ai` → 내 GitHub로 `push`** 하는 일이다.
- 강의 데이터가 필요하면 Claude Code가 `kma-auto-genai-3-1/data/DayN`에서 `my-kma-auto-ai/data/DayN`으로 **복사**한다.
- 강의 저장소 폴더 안에서 직접 작업하지 않는다. 고쳐도 올릴 수 없고, 다음 날 새로 받을 때 충돌이 난다.

## 1. 메타 프롬프트란?

| | 일반 프롬프트 | 메타 프롬프트 |
|---|---|---|
| 누가 순서를 짜나 | 내가 단계를 다 적는다 | **Claude Code가** 계획을 짠다 |
| 길이 | 길고 전문 용어가 많다 | 짧다. 목표와 진행 방식만 |
| 모르는 정보 | 내가 미리 알아야 한다 | Claude Code가 **물어본다** |
| 초보자 | 쓰기 어렵다 | 그대로 붙여 넣으면 된다 |

**메타 프롬프트 = "어떻게 할지"를 Claude Code가 짜도록 맡기는 프롬프트.**
세 부분이면 충분하다.

1. **나는 누구인가** — "나는 Git을 처음 써 보는 완전 초보야"
2. **목표** — "오늘 수업 결과물을 GitHub 저장소에 챕터로 올리고 싶어"
3. **진행 방식** — "한 번에 하나씩 물어봐 줘 · 번호 보기를 줘 · 하기 전에 한 줄로 설명해 줘 · 내가 할 일은 멈추고 알려 줘"

> [!tip] 왜 이렇게 하면 초보자도 될까?
> 무엇을 물어야 하는지, 어떤 순서로 해야 하는지는 Claude Code가 더 잘 안다. 나는 **내 상황에 대한 질문에만** 답하면 된다. 그리고 진행 방식에 "번호 보기"를 넣었기 때문에 대부분 숫자 하나로 답할 수 있다.

## 3. 처음 한 번 ① — GitHub 가입 (가입 도우미)

### 3.0 누가 무엇을 하나

GitHub 가입은 **내 계정**을 만드는 일이라 비밀번호·인증 코드 입력은 **반드시 내가** 한다. 대신 Claude Code가 **가입 화면을 열어 주고, 화면마다 무엇을 입력할지 안내**한다.

| 단계 | 누가 | 하는 일 |
|---|---|---|
| 가입 화면 열기 | Claude Code | 브라우저로 `github.com/signup`을 연다 |
| 화면 안내 | Claude Code | 지금 화면에서 무엇을 입력하는지 한 단계씩 알려 준다 |
| 이메일·비밀번호·아이디 입력 | **나** | 비밀번호는 Claude Code에게도 말하지 않는다 |
| 퍼즐·이메일 인증 코드 | **나** | 사람인지 확인하는 단계 — 대신해 줄 수 없다 |
| 다음 단계 준비 | Claude Code | 가입이 끝나면 저장소 만들기(M0)로 넘어간다 |

> [!danger] 절대 Claude Code에게 알려 주지 않는 것
> GitHub **비밀번호**, 이메일로 온 **인증 코드**, 2단계 인증 **복구 코드**. Claude Code도 묻지 않도록 가입 도우미 프롬프트에 적어 두었다.

### 3.1 준비 — Claude Code 켜기 (상위 폴더 KMA_3-1)

1. 문서 폴더 안에 `KMA_3-1` 폴더를 만든다. (빈 폴더면 된다. 안의 두 폴더는 Claude Code가 만든다)
2. **Claude 데스크톱 앱 → Code 탭** → 작업 폴더로 `KMA_3-1` 선택

### ✍ 3.2 MS 시작 도우미 — 필요한 강의 자료만 받고 내 폴더 준비하기 (모든 수강생)

> [!warning] 강의 저장소를 통째로 받지 않는다
> 강의 저장소 전체는 약 **470MB**다. 대부분이 Hook 케이스 **동영상(mp4)** 과 보충교재라 오늘 실습에는 필요 없다. 그래서 **필요한 것만 골라 받는다**(Git의 sparse checkout — 저장소 일부만 받는 기능). Claude Code가 알아서 처리한다.
>
> | 받는 범위 | 내용 | 크기(대략) |
> |---|---|---|
> | **1) Day 3만 (기본)** | `Day3_경쟁사재무`의 PDF 4개 + `data/Day3` | 1MB 안팎 |
> | 2) Day 0~6 본 강의 | 날마다 본 강의(Main) PDF + `data` 폴더 전체 | 수 MB |
> | 받지 않음 | 동영상(mp4) · 보충교재 · HTML | — |

```text
나는 Git을 처음 써 보는 완전 초보야. 너는 수업 시작 도우미야.

[목표]
지금 열린 KMA_3-1 폴더 안에 두 폴더를 준비하고 싶어.
1. kma-auto-genai-3-1 — 선생님 강의 저장소 https://github.com/keerhee/kma-auto-genai-3-1 의 사본.
   전체는 너무 크니 필요한 것만 받아 줘. 받을 범위를 번호 보기로 물어봐 줘.
   1) Day3_경쟁사재무 폴더의 PDF와 data/Day3만
   2) Day0~Day6 각 날의 본 강의(Main) PDF와 data 폴더
   동영상(mp4)과 보충교재는 어느 경우든 받지 마.
   나는 이 폴더를 고치지 않고 받기만 할 거야. 나중에 다른 Day 자료도 추가로 받을 수 있게 해 줘.
2. my-kma-auto-ai — 내 수업 결과물을 챕터로 쌓을 빈 폴더. (GitHub 연결은 나중에 할 거야)

[진행 방식]
- 각 단계를 하기 전에 무엇을 왜 하는지 쉬운 말 한 줄로 설명해 줘.
- Git이 없으면 설치해 줘. 강의 저장소는 공개 저장소라 로그인 없이 받을 수 있을 거야.
- 받은 뒤에는 받은 파일 목록과 전체 크기를 보여 주고, 두 폴더의 차이를 한 줄씩 설명해 줘.
```

✅ 확인: `KMA_3-1` 안에 두 폴더가 있고, `kma-auto-genai-3-1/Day3_경쟁사재무`에 PDF 4개(동영상 없음), `data/Day3`에 CSV 4개가 있다.

> [!tip] 다음 날 자료를 더 받을 때
> Day 4 수업 전에는 이렇게 말한다: `강의 자료에서 Day4 PDF와 data/Day4도 받아 줘`
> 선생님이 자료를 고치면: `강의 자료 새로 받아 줘` (git pull). 매일 "챕터 올리기" 때도 Claude Code가 먼저 새로 받는다.

### ✍ 3.3 GA 가입 도우미 — 계정이 없을 때만

```text
나는 GitHub 계정이 없는 완전 초보야. 너는 GitHub 가입 도우미야.
- 먼저 내 브라우저로 GitHub 가입 페이지(https://github.com/signup)를 열어 줘.
- 그다음 화면마다 무엇을 입력하고 무엇을 눌러야 하는지 한 단계씩 쉬운 말로 알려 줘. 내가 "다음"이라고 하면 다음 단계를 알려 줘.
- 아이디를 정할 때는 회사·포트폴리오에 써도 어색하지 않은 아이디 규칙을 알려 줘.
- 내 비밀번호, 이메일로 온 인증 코드, 복구 코드는 절대 묻지 마. 나도 말하지 않을게.
- 가입이 끝나면 다음에 할 일을 알려 줘.
```

### ✍ 3.4 가입 화면 하나씩 보기 (브라우저에 입력)

화면 모양은 GitHub가 바꿀 수 있다. 순서와 내용은 대체로 아래와 같다.

| 순서 | 화면 | 입력할 것 | 주의 |
|---|---|---|---|
| 1 | 이메일 | 자주 확인하는 이메일 | 회사 메일보다 **개인 메일** 권장 (퇴사해도 계정 유지) |
| 2 | 비밀번호 | 새 비밀번호 | **15자 이상**, 또는 **8자 이상 + 숫자 + 영문 소문자**. 다른 사이트와 같은 비밀번호 금지 |
| 3 | 아이디(username) | 영문·숫자·하이픈(-) | 하이픈으로 시작·끝 불가. 예: `hong-gildong`, `gildong-auto`. 저장소 주소가 `github.com/아이디`가 된다 |
| 4 | 이메일 소식 수신 | 체크 해제해도 된다 | 선택 사항 |
| 5 | 퍼즐 확인 | 화면 지시대로 | 사람인지 확인. 안 풀리면 새로고침 |
| 6 | 이메일 인증 코드 | 메일로 온 숫자 코드 | 메일이 안 보이면 **스팸함** 확인 |
| 7 | 로그인 · 간단한 설문 | 건너뛰어도 된다 | 요금제는 **Free** |

> [!tip] 더 쉬운 방법 — Google 계정으로 가입
> 가입 화면의 **Continue with Google**을 누르면 Google 계정으로 바로 가입할 수 있다. 비밀번호를 새로 만들 필요가 없다. 이 경우에도 아이디(username)는 정해야 한다.

✅ 가입 확인: `github.com`에 로그인된 상태로 오른쪽 위에 내 프로필 그림이 보인다. 이메일 인증을 안 하면 **저장소를 만들 수 없으니** 6번을 꼭 끝낸다.

### ✍ 3.5 2단계 인증(2FA) 안내가 나오면 (필요할 때만)

GitHub는 코드를 올리는 사용자에게 **2단계 인증**(비밀번호 + 휴대폰 앱 코드)을 요구할 수 있다. 안내가 나오면 정해진 기간(보통 45일) 안에 설정하라는 뜻이다. 오늘 바로 하지 않아도 저장소 만들기는 진행할 수 있다.

```text
GitHub에서 2단계 인증을 설정하라는 안내가 나왔어. 무엇인지 쉬운 말로 설명하고, 휴대폰 인증 앱으로 설정하는 순서를 한 단계씩 알려 줘. 코드와 복구 코드는 묻지 마.
```

- 설정 중에 나오는 **복구 코드(recovery codes)** 는 내려받아 **KMA_3-1 폴더가 아닌 곳**에 보관한다. 실수로 GitHub에 올리면 안 된다.

## 4. 처음 한 번 ② — 저장소 만들기 (M0 설정 도우미)

### ✍ 4.1 M0 — 그대로 복사해서 붙여 넣기

```text
나는 Git과 GitHub를 처음 써 보는 완전 초보야. GitHub 가입과 강의 자료 받기(MS)는 끝냈어. 너는 친절한 설정 도우미야.

[목표]
```

### 4.2 M0가 안에서 하는 일 — 허락 요청 읽는 법 (참고 · 입력 없음, 허락 버튼만)

M0를 붙이면 Claude Code가 아래 순서로 일하며, 명령을 실행할 때마다 **허락 요청**이 뜬다. 왼쪽 열의 명령이 보이면 **허락해도 되는 정상 단계**다. 명령 모양은 컴퓨터마다 조금 다를 수 있다.

| 순서 | 허락 요청에 보이는 명령 (예) | 쉬운 뜻 | 나 |
|---|---|---|---|
| 1 | `git --version` | Git이 깔려 있는지 확인 | 허락 |
| 2 | `winget install Git.Git` (Windows) · `xcode-select --install` (Mac) | 없으면 Git 설치 | 허락 (설치 창이 뜨면 기본값으로 진행) |
| 3 | `git config --global user.name ...` · `user.email ...` | 이름표 등록 | 허락 |
| 4 | `gh --version` → 없으면 `winget install GitHub.cli` · `brew install gh` | GitHub를 다루는 도구 설치 | 허락 |
| 5 | `gh auth login --web` | GitHub 로그인 시작 | 허락 → **아래 4.3을 내가 직접** |
| 6 | 파일 만들기 (my-kma-auto-ai의 README.md · .gitignore · 00_오늘결과물, KMA_3-1의 CLAUDE.md) | 저장소 뼈대 · 작업 규칙 | 허락 |
| 7 | `git init` → `git add` → `git commit` (my-kma-auto-ai 안에서) | 세이브 켜기 · 첫 저장 지점 | 허락 |
| 8 | `gh repo create my-kma-auto-ai --private --source=. --push` | GitHub에 **Private** 저장소를 만들고 올리기 | `--private`인지 확인 후 허락 |
| 9 | `gh repo view --web` | 브라우저로 저장소 열기 | 허락 |

> [!warning] 이런 명령은 바로 허락하지 않는다
> `rm`, `del`, `--force`, `reset --hard`처럼 **지우거나 덮어쓰는** 말이 있으면 거절하고 "이 명령이 왜 필요한지 먼저 설명해 줘"라고 묻는다. 8번에서 `--public`이 보여도 거절하고 Private으로 바꿔 달라고 한다.

### ✍ 4.3 GitHub 로그인 — 내가 직접 하는 단 한 번 (브라우저에 입력)

> [!question] 8자리 코드가 무엇인가?
> **일회용 로그인 코드**(device code)다. 내 컴퓨터의 Claude Code(GitHub 도구 `gh`)가 **내 GitHub 계정을 써도 되는지** 브라우저에서 확인하는 데 쓴다.
> - 모양: 영문·숫자 8자리, 가운데 하이픈 (예: `ABCD-1234`)
> - **비밀번호가 아니다.** GitHub 비밀번호는 Claude Code에 절대 입력하지 않는다.
> - **15분 안에 한 번만** 쓴다. 시간이 지나면 Claude Code에게 "코드 다시 받아 줘"라고 한다.
> - 이 코드를 남이 입력하면 그 사람 컴퓨터가 내 계정에 연결될 수 있다. **절대 공유하지 않는다.**

5번 단계에서 Claude Code가 멈추고 안내한다. 보통 이 순서다.

1. **Claude 데스크톱 앱의 Claude Code 화면**에 일회용 코드(예: `ABCD-1234`)가 나온다 → 복사
2. 브라우저에서 `github.com/login/device`가 열린다 (안 열리면 주소창에 직접 입력)
3. GitHub에 로그인돼 있지 않으면 먼저 로그인
4. 코드를 붙여 넣고 **Continue**
5. 권한 요청 화면에서 앱 이름이 **GitHub CLI**인지 확인하고 **Authorize**
6. "Congratulations, you're all set!" 같은 완료 화면이 나오면 Claude Code에게 `끝났어`

> [!danger] 인증 코드는 나만
> 일회용 로그인 코드를 옆 사람·단체 채팅에 공유하지 않는다. 내가 시작하지 않은 로그인 요청이면 **Authorize하지 않는다.**

### 4.4 실제로 이렇게 진행된다 (예시)

```text
Claude  GitHub 아이디를 알려 주세요.
나      hong-gildong
Claude  Git에 기록할 이메일은 GitHub 가입 이메일을 쓰는 게 좋아요. 이메일을 알려 주세요.
나      me@mail.com
Claude  (설명) Git이 설치돼 있는지 확인할게요.          → 허락 요청 → 허락
Claude  (설명) GitHub를 다루는 도구(gh)를 설치할게요.   → 허락 요청 → 허락
Claude  이제 GitHub 로그인이 필요해요. 직접 해 주세요.
        ① 화면의 일회용 로그인 코드(예: ABCD-1234) 복사  ② github.com/login/device
        ③ 코드 입력 → Continue → Authorize  ④ 끝나면 '끝났어'
나      끝났어
Claude  저장소를 Private으로 만들어 올릴게요.            → 허락 요청 (--private 확인) → 허락
Claude  완료! https://github.com/hong-gildong/my-kma-auto-ai (Private)
        KMA_3-1/CLAUDE.md에 규칙과 '챕터 올리기' 절차를 적어 두었습니다. 브라우저로 열었어요.
```

✅ 끝나면 확인할 것
1. 브라우저에서 저장소 이름 옆에 **Private**이 보인다.
2. 저장소 첫 화면에 `README.md`, `.gitignore`가 보인다. `00_오늘결과물`은 **보이지 않아야** 정상이다(올라가지 않게 했으므로).
3. 내 컴퓨터의 `my-kma-auto-ai`를 열면 `00_오늘결과물` 폴더는 있다.
4. `KMA_3-1/CLAUDE.md`를 열면 두 폴더의 역할과 '챕터 올리기 절차'가 적혀 있다. (CLAUDE.md는 내 컴퓨터에만 있는 작업 규칙이라 GitHub에는 없다)

### ✍ 4.5 Claude Code로 저장소가 안 만들어질 때 — 웹에서 직접 (예비 경로)

회사 PC 보안 정책으로 도구 설치가 막히는 경우가 있다. 그때는 웹에서 빈 저장소를 만들고, 연결만 Claude Code에게 맡긴다.

1. `github.com` 로그인 → 오른쪽 위 **+** → **New repository**
2. 입력 화면

| 항목 | 입력 | 이유 |
|---|---|---|
| Owner | 내 아이디 (그대로) | |
| Repository name | `my-kma-auto-ai` | 영문·숫자·하이픈 |
| Description | `능률협회 자동차산업과 생성형 AI 3-1 학습 노트` | 선택 |
| 공개 범위 | **Private** | Day 6 점검 전까지 비공개 |
| Add a README file | **체크하지 않는다** | 내 폴더의 README와 충돌을 막는다 |
| .gitignore · License | **None** | Claude Code가 만든다 |

3. **Create repository** → 나오는 화면 위쪽의 주소(`https://github.com/내아이디/my-kma-auto-ai.git`)를 복사
4. Claude Code에게:

```text
GitHub에 빈 저장소를 직접 만들었어. 주소는 [복사한 주소]야. my-kma-auto-ai 폴더를 이 저장소에 연결해서 올려 줘. 나머지는 M0의 진행 방식과 마무리대로 해 줘.
```

- Git 자체가 설치되지 않으면 강사에게 알린다(회사 PC 관리자 권한이 필요할 수 있다).

## ✍ 7. Day 6 — M4 공개 도우미

```text

```

- **커밋 기록까지** 점검하는 이유: 파일을 지워도 예전 커밋에는 남아 있다.
- 공개 후 `github.com/내아이디/my-kma-auto-ai` 한 줄을 이력서·면담 자료에 붙인다.

## 8. 한 장 요약

| 언제 | 붙여 넣을 것 | 내가 하는 일 |
|---|---|---|
| 계정이 없을 때 | **GA 가입 도우미** | 이메일·비밀번호·아이디 입력, 퍼즐·인증 코드 (비밀번호는 나만) |
| 수업 시작 (모두) | **MS 시작 도우미** | 강의 자료 받기 · 두 폴더 확인 |
| Day 3 처음 한 번 | **M0 설정 도우미** | 질문에 답하기 · 허락 요청 읽기 · GitHub 로그인 승인 · Private 확인 |
| 매일 수업 후 | 결과물을 `00_오늘결과물`에 넣고 **`챕터 올리기`** | 번호로 답하기 · 파일 목록 보고 허락 · 브라우저 확인 |
| 막힐 때 | **M2** 한 줄 / 하고 싶은 일은 **M3** | 설명 읽고 하나씩 따라 하기 |
| Day 6 | **M4 공개 도우미** | 점검 결과 확인 후 공개 허락 |

> [!warning] 그래도 바뀌지 않는 원칙
> 1. 사내 BOM·원가·협력사 단가·고객 정보·API 키는 **어떤 경우에도** 올리지 않는다.
> 2. **파일 목록을 보기 전에는** 올리기를 허락하지 않는다.
> 3. 모르는 명령이 허락 요청에 나오면 거절하고 **M2**를 붙여 넣는다.

## 부록 (강사용) — 메타 프롬프트가 만들어 내는 상세 작업

M0가 CLAUDE.md에 적는 절차는 I판의 상세 프롬프트 P0~P5와 같은 내용이다. 수강생 화면에서 Claude Code가 절차를 빼먹으면 아래 항목을 기준으로 지적한다.

- 구조: `KMA_3-1/`(Code 탭에서 여는 폴더, CLAUDE.md) 안에 `kma-auto-genai-3-1/`(강의 사본, pull만)과 `my-kma-auto-ai/`(내 저장소, push)
- 폴더: `DayN_주제/`, `data/DayN/`, 파일명은 `DayN_`으로 시작, `00_오늘결과물/`은 `.gitignore`
- 점검: 사내 자료·개인정보·API 키/비밀번호, 실데이터 CSV 출처 열, 가상 데이터 `가상` 표기, `.pptx` 원본·100MB 초과 파일
- 목차: README 표 `챕터 | 핵심 결론 한 줄 | 폴더`
- 올리기: 변경 목록 제시 → 수강생 확인 → `DayN 주제 챕터 추가` 메시지로 commit·push

# Day2 전체 갱신

규칙은 `CLAUDE.md`에 있다. 여기에 다시 쓰지 않는다.

## 역할
input이 바뀐 뒤 무엇이 낡았는지 가려내고, 낡은 판단은 다시 하게 만드는 갱신 담당.
**스크립트를 다시 돌렸다고 갱신이 끝난 것이 아니다.** Claude가 읽고 판단한 결과는 다시 읽어야 바뀐다.

## 절차
① `python working/scripts/run_all.py` 를 실행하고 출력을 그대로 보여 준다.
   - 종료 코드 0: 모두 최신. ⑤로 간다.
   - 종료 코드 2: "다시 판단 필요" 항목이 있다. ②로 간다.
   - 종료 코드 1: 스크립트 오류. 메시지를 보여 주고 멈춘다.
     `[중단] 집계기준이 하나로 정해지지 않음`은 오류가 아니라 **사람 확인 ①**이다 — 원본 표의 기준 열을 보여 주고 묻는다.
② "다시 판단 필요" 항목마다 해당 스킬 절차를 처음부터 다시 따른다.
   | 항목 | 스킬 |
   |---|---|
   | 03 VOC 키워드 | `VOC-감정분석` (사람 확인 ② 포함) |
   | 04 차트 클리닉 | `차트-클리닉` (한 줄 메시지 선택 포함) |
   예전 분류표·진단표를 고쳐 쓰지 말고 바뀐 input을 처음부터 읽는다.
   예전 결과와 비교해 달라진 점(예: 부정 최다 주제가 바뀜)은 따로 적어 둔다.
③ 각 스킬의 마지막 단계에서 `stamp.py`로 판단 기록을 남긴다. **다시 판단하지 않고 기록만 새로 찍지 않는다.**
   (그래도 분류표 리뷰 원문이 input과 다르면 `s2_voc.py`와 결과화면이 잡아낸다.)
④ `python working/scripts/run_all.py` 를 다시 실행해 종료 코드 0을 확인한다.
⑤ 사람 확인 ③(제출 전 역검토)을 한다 — `output/운영안내/2_붙여넣는_프롬프트.md`의 역검토 프롬프트.
⑥ `working/프롬프트_기록.md`에 한 줄 남긴다. `working/갱신기록.md`는 run_all이 자동으로 남긴다.

## run_all이 하는 일 (참고)
- input 파일 지문을 지난 실행과 비교해 바뀐 파일을 보고한다(`working/_input_manifest.json`).
- 01 EV 시장 · 02 도구 기준표 · 05 주간 수집 · 00 결과화면은 바로 다시 만든다.
- 03 · 04는 판단 기록(`working/_판단기록.json`)이 지금 input과 맞을 때만 다시 만든다.
  맞지 않으면 예전 xlsx를 `output/_이전판/`으로 옮기고(지우지 않음) 결과화면에 경고 카드를 띄운다.
- Top5는 `input` 백업과 `working/수집_EV_Top5_*.csv` 중 **가장 최근에 바뀐 파일**을 쓴다.
  input을 새로 넣었는데 예전 수집본이 쓰였다면 출력의 "입력:" 줄을 보고 알린다.

# Day2 · 자동차 데이터 수집과 시각화 — Claude Code 운영판 작업 규칙

자동차특화 AI 융합 전문가 과정 2일차 실습을 Claude Code 한 곳에서 진행하기 위한 규칙이다.
원래 과정의 Perplexity·ChatGPT·Claude·Google Sheets 역할을 이 폴더 안에서 처리하고,
산출물은 **xlsx(고치는 표)** 와 **단일 HTML(보여 주는 화면)** 두 형식으로 만든다.

## 1. 원본 보존
- `input/` 파일은 수정·삭제·이동하지 않는다.
- 새로 수집하거나 Claude가 만든 표는 `working/`에, 최종 산출물은 `output/`에 둔다.

## 2. 숫자에는 항상 기준을 붙인다 (이날의 핵심 함정)
- 모든 판매·등록 수치에 **집계기준(판매/출고/등록) · 기간 · 출처 · 기준일**을 함께 적는다.
- 기사가 "판매"라고 써도 수치가 등록대수면 **등록**으로 적는다.
  `input/Day2_국내EV판매_Top5_실데이터.csv`는 열 이름이 `판매량(대)`이지만 값은 신규등록 대수다.
- 기준이 다른 숫자(판매↔등록, 내수↔수출 포함, KAMA↔KAIDA)는 한 차트·한 합계에 섞지 않는다.
  섞어야 하면 기준이 바뀌는 지점을 차트에 표시하고 출처를 둘 다 적는다.
- 출처마다 값이 다르면 둘 다 적는다. 고르지 않는다.
  (예: 2025년 전기차 신규등록 KAMA 220,177대 · 데일리카 220,896대)

## 3. 가상·추정·확인 필요 표기
- `_가상` 파일과 Claude가 생성한 리뷰는 "가상 데이터(실습용)"로 표기한다. 사실처럼 단정하지 않는다.
- 가정으로 계산한 값(절감 시간 등)에는 "추정"을 붙인다.
- 웹에서 찾지 못한 값은 비워 두고 "확인 필요"로 적는다. 추측으로 채우지 않는다.
- 데이터에 없는 시장 전체 합계·점유율을 만들어 내지 않는다.
  Top5만 있으면 비중은 "Top5 내 비중"이라고 적는다.
- 상관관계를 인과관계로 서술하지 않는다.

## 4. 웹 수집 규칙 (Perplexity 역할)
- 웹 검색으로 찾은 수치는 출처 URL을 열어 본문에서 숫자를 다시 확인한 뒤 표에 넣는다.
- 수집 결과는 `working/수집_<주제>_<YYYYMMDD>.csv`로 저장하고, 열에 `출처URL · 게시일 · 집계기준 · 확인상태`를 둔다.
- `input/`의 실데이터(기준일 2026-10-07)와 겹치는 항목은 값을 대조해 차이를 적는다.

## 5. 차트 원칙 (본 강의 3.2)
1. 한 차트에 한 메시지. 차트 제목은 그 메시지를 한 줄로 쓴다.
2. 막대 차트의 y축은 0에서 시작한다. 차이는 데이터 레이블로 보여 준다.
3. 3D·그림자·무늬 같은 장식을 쓰지 않는다.
4. 색은 강조할 한 곳에만 쓰고 나머지는 회색 계열로 둔다.
- 차트 아래에 `기준 · 기간 · 출처`를 적는다.
- 데이터 성격과 차트를 맞춘다: 순위·크기는 막대, 시간 흐름은 선, 구성비는 누적 막대, 두 기준 위치는 산점도.

## 6. 산출물 형식
- 문서는 한국어 마크다운.
- **xlsx**: 수강생이 열어 숫자를 확인하고 고치는 표. 엑셀 내장 차트를 넣고, 비중은 값이 아니라 **수식**으로 넣는다.
  xlsx는 `working/scripts/d2lib.py`의 `write_xlsx`로 만든다.
- **HTML**: 보여 주는 화면. 단일 파일, 외부 CDN·API 호출 금지, 데이터와 이미지는 파일 안에 넣는다.
  HTML은 `working/scripts/d2lib.py`의 SVG 함수로 만든다.
- 산출물 이름은 `output/NN_이름.xlsx|html|md` 형식을 따른다.

## 7. 사람 확인 (멈추는 지점)
다음 세 지점에서는 작업을 멈추고 수강생(사용자)에게 확인을 받는다.
1. 수집한 수치의 **집계기준** 확정 (판매인가 등록인가, 기간은 언제인가)
2. VOC **키워드 사전**(같은 뜻 키워드를 하나로 묶는 표) 확정
3. 보고서·발표 자료 **제출 전 역검토** 결과 확인

## 8. 기록
- 사용한 프롬프트와 결과 파일을 `working/프롬프트_기록.md`에 남긴다(재현성 요건).
  기록 항목: 단계 · 프롬프트 요지 · 산출 파일 · 사람 확인 여부.

## 9. input이 바뀌었을 때
- 결과는 자동으로 바뀌지 않는다. `Day2-전체갱신` 스킬로 다시 만든다.
- Claude가 읽고 판단해 만든 파일(VOC 분류·키워드 사전, 차트클리닉 진단표·메시지)은 만든 직후
  `working/scripts/stamp.py`로 **어떤 입력을 보고 만들었는지** 기록한다(`working/_판단기록.json`).
- 입력이 바뀐 판단 결과로 산출물을 만들지 않는다. 다시 판단하지 않고 기록만 새로 찍지 않는다.
- 예전 input 기준 산출물은 지우지 않고 `output/_이전판/`으로 옮긴다. 이 폴더의 파일은 배포하지 않는다.

## 폴더 구조
```
input/              원본(읽기 전용) — 과정 저장소 data/Day2 사본
working/            수집 결과, Claude 분류표, 스크립트, 프롬프트 기록
working/scripts/    d2lib.py(공통) · 단계별 스크립트 · run_all.py(전체 갱신) · stamp.py(판단 기록)
output/             xlsx · HTML · md 산출물
output/_이전판/      예전 input 기준 산출물(배포 금지)
output/운영안내/     수강생·강사용 진행 안내 (코드 없이 읽는 문서)
docs/               원본 덱 대응표, 강사용 모범답안
.claude/skills/     반복 절차 스킬 5개
```

### 스킬 — 절차는 여기에 있다

| 스킬 | 언제 쓰나 | 원 과정 위치 |
|---|---|---|
| `EV-시장수집` | 국내 EV 판매·등록 수치를 모아 Top5 표와 막대 차트를 만들 때 | 본 강의 ② 데이터 · ④ 분석1 |
| `VOC-감정분석` | 리뷰를 주제·감정·키워드로 나누고 누적 막대로 보여 줄 때 | 본 강의 ③ 전처리 · ⑤ 분석2 |
| `차트-클리닉` | 이미 있는 차트를 원칙·함정으로 진단하고 다시 그릴 때 | 보강 실습 A |
| `주간-수집레시피` | 매주 반복할 수집·검증 절차를 만들고 시범 실행할 때 | 보강 실습 B |
| `Day2-전체갱신` | `input/`을 바꾼 뒤 산출물 전체를 다시 만들 때 | — (운영) |

규칙은 이 문서에 두고 **스킬에 다시 쓰지 않는다.**
수업 진행 순서는 `output/운영안내/1_수업_진행순서.md`, 붙여 넣을 프롬프트는
`output/운영안내/2_붙여넣는_프롬프트.md`에 있다.
